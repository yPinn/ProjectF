# Lessons

## 2026-10-20：編輯指南必須能讓非技術人員照做

- 使用者要求再次精簡潤色，清楚指出要改哪裡、怎麼操作；不能只把設定欄位與工程指令列在 README。
- 規則：README 保留任務入口，按成員資料、素材上傳、儲存發布拆成短流程；每段說明檔案位置、點擊操作、修改範例與完成後的確認方式。
- 規則：工程設定另放技術補充；解釋必要名詞與 main 儲存的發布效果，使用者不必先學會本機建置才能日常編輯。

## 2026-10-20：歷史照片恢復不等於找回使用者指定的新照片

- 使用者指出 Jenny 歷史有效原圖不是要使用的那張；不能將「可解碼的舊圖」直接當成「已修復的新圖」。
- 規則：先查不同歷史圖片版本，再確認目標照片；如果只有舊版與無圖片資料的空檔，明確要求完整的新原圖，避免重複上傳錯誤版本。
- 本次進一步遍歷歷史 blob 後，找到 f8bad628 的新上傳：1108×1189、2,770,849 bytes，可完整解碼。先前只比對損壞檔與更早原圖，漏掉中間有效版本；以最新有效上傳恢復原指定路徑。

## 2026-10-20：選人舞台裝飾與互動內容不得意外反白

- 使用者回報拖曳時背景 FUCK ENT. 被選取；pointer-events: none 只影響滑鼠命中，不能取代 user-select: none。
- 規則：在拖曳／滑動互動舞台內，明確限制文字選取與圖片原生拖曳，包含 WebKit；不要為修正裝飾文字而全站禁止選取，也不要用 preventDefault 阻止正常垂直捲動。

## 2026-10-20：介紹容量與 brief 應一起設定

- 規則：先量測實際字級與被截掉的內容，再小幅增加寬高；不能只提高資料字數上限，卻保留 CSS 固定四行裁切。
- 規則：描述容量增加時，短視窗須保留自然成長空間，驗證姓名、遊戲、CTA 與導覽不重疊；只調整 Info，不讓 Clip 連帶改版。
- 規則：提供建議字數與程式上限兩種資訊，說清楚標點、英文及空白如何計數；brief 維持精簡，不把畫面擴成長篇閱讀頁。

## 2026-10-20：來源與生成檔不可要求維護者手動同步

- 規則：Git 上更新原圖後，標準 build 必須自行驗證與生成衍生素材，所需工具須鎖定於專案相依，不能依賴代理專用的本機套件路徑。
- 規則：使用內容雜湊網址處理換圖快取，所有人物／Logo／遊戲引用都讀同一份生成清單；不能只更新其中一個使用端。
- 規則：設定有填但錯誤時讓建置失敗；尚未準備的可選資料以 null 明確表示，避免把壞路徑當成正常替代。
- 規則：帳號修改須涵蓋來源、聯絡 key、API 名單與瀏覽器快取版本；展示縮圖不再被 API 頭像悄悄覆蓋。
- 規則：驗收同時包含乾淨依賴／無生成檔建置、同名換圖後完整重建，以及損壞圖片必須失敗，不能只看 build exit 0。

## 2026-10-20：區分 Git 更新、建置輸出與正式站素材

- 使用者補充：問題發生於後續 Git 更新後的 Cloudflare Pages rebuild，不能只依上一輪本機已通過驗證推斷目前狀態。
- 規則：先比較新增提交及實際建置來源，再查 UI 使用的素材清單與衍生檔案；更新原圖不代表既有最佳化素材自動更新。
- 規則：把素材生成做成獨立手動步驟時，必須明確說明 Git 網頁換圖後的必要流程；長期應讓標準建置自動處理並納入套件相依。
- 規則：圖片副檔名與檔案存在不足以證明有效，須檢查可解碼性；同網址更新的素材也要處理瀏覽器快取版本。

## 2026-10-19：Clip 顯示範圍與導覽對齊

- 使用者要求 Clip 內容區只保留播放器，遊戲與 Watch Live 僅在 Info 顯示。
- 規則：新增內容模式時，明確限制各模式的內容，不自動保留其他模式的附屬操作。
- 規則：混用按鈕、連結與停用文字的導覽，須共用顯示方式、垂直對齊及最小高度，並驗證桌機與手機。

## 2026-10-19：展示框主題色使用半透明背景

- 使用者補充要求半透明填色；框內背景使用各人物主題色 30% alpha。
- 規則：只對背景色套透明度，不用整個展示元素的 opacity 改變人物照片；沿用各人物獨立色彩，避免左右人物都繼承中央人物主題色。

## 2026-10-19：修改展示入口時，詳細資訊也必須使用真實資料驗證

- 使用者回報詳細區跑版：只渲染存在的遊戲項目，導致 1–2 個圖示自動平分整排而變得過大；人物標題與導覽也受到擠壓。
- 規則：移除既有佔位元素前，先確認它是否承擔版面尺寸約束；遊戲清單須使用固定四欄或明確的圖示尺寸上限。
- 規則：改變標題語意標籤時，同步更新所有樣式選擇器；驗證入口與詳細頁、2 個與 4 個遊戲、長姓名，以及使用者提供的實際視窗大小後才回報完成。
- 此次修正屬原任務範圍，直接處理，不再要求計畫確認。

## 2026-10-19：不要擴充原有介紹頁的控制項

- 使用者明確要求移除新增的「上一位／頁碼／下一位」及「返回陣容」。
- 規則：本次範圍是新展示入口與效能改善；詳細介紹保留原有導覽，不自行新增重複控制項。檢查桌機與手機的實際畫面，確認沒有遺留新增按鈕及樣式。
